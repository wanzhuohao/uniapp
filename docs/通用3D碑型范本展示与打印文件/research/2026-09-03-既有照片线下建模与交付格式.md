## 二、假设与判据

- 当前假设:
  - 现有照片至少包含一张清晰正面照；可能缺少完整环绕视角。
  - 用户接受通用无字范本，不要求未拍摄面的测量级真实复刻。
  - 平台只展示最终资产，Bambu Studio 负责具体打印机切片。
- 通过判据:
  - 有证据证明现有 Web 技术栈能加载适合发布的三维格式。
  - 有证据证明 Bambu Studio 能导入计划交付的打印格式。
  - 对照片不足定义不依赖补拍的明确降级路径，且不会把推测部分宣传成实拍复原。
- 失败判据:
  - 必须重新采集完整照片才能满足所有验收标准。
  - 只能得到贴图或开放曲面，无法修复为可切片实体。
  - 交付格式不能被现有平台或 Bambu Studio 读取。

## 七、结论分层

### 已验证事实

- 当前项目已有 Three.js，但现有 3D 预览是程序化几何与纹理，不会自动加载照片建模产物。
- Three.js 可通过官方 `GLTFLoader` 加载 glTF/GLB，GLB 适合作为平台展示资产。
- Bambu Studio 官方代码明确把 STL 列为支持格式。
- STL 本身不携带可靠的物理单位语义，因此“能导入并切片”不能独立证明制造尺度正确。
- 二进制 STL 每个三角面记录带有 2 字节 attribute byte count；总长度与 EOF 正常并不能证明该字段无隐藏数据，通用无字发布物需逐面将其限定为 `0x0000`。
- 传统摄影测量需要不同视角和图像重叠；未查看实际照片前不能判断照片是否足以自动恢复完整石碑。
- 用户已经明确接受“通用无字范本”与线下建模，并取消在线重建和打印机直连。
- 线下建模工作域与 UniApp 发布仓库已分离：原始照片和中间产物不进入 UniApp，只有通用无字的最终资产可进入发布环节。
- 即使模型表面无字，GLB 任意 JSON 对象键/字符串值、扩展对象、未引用或尾随字节、内嵌/外链纹理元数据，或 STL 头部/尾部仍可能携带原始文件名、个人信息或本机路径，必须在跨工作域发布前执行覆盖整文件结构、默认拒绝的机器扫描。

### 基于事实的推论

- 即使照片不满足完整摄影测量，只要正面轮廓和主要结构可辨识，仍可采用“照片可验证部分 + 石碑规则几何补全 + 网格修复”的混合建模，形成可展示、可切片的通用范本。
- 缺失面的结果属于设计补全而非真实还原，必须在页面或模型说明中标注，避免精度误导。
- GLB 与 STL 分开交付比用一个文件兼顾展示和制造更稳妥：GLB 保留材质表现，STL 聚焦封闭几何。

### 历史决定（当前首版不执行）

- 本节只适用于未来取得照片且该照片增量完成独立需求/设计评审之后，不是当前无照片首版的开发前置或 02 出口门禁。
- 未来增量不要求重新拍摄；届时再对照片做只读分级：完整多视角、有限多视角、单/少视角。
- 未来增量允许摄影测量、人工建模和算法辅助混合使用，不把单一摄影测量工具写成需求约束。
- 平台展示强制交付 GLB；拓竹打印强制交付 STL；3MF 暂不作为首版必需产物。
- 若启动未来增量，原始照片仍只在线下本机处理，平台不新增照片和建模服务。
- 目录职责固定为 `source-photos` 输入、`workspace` 中间处理、`exports` 最终输出；UniApp 不作为建模工作目录。
- `exports → UniApp` 使用闭合脱敏门禁：最终 GLB 禁止外链，递归扫描全部 JSON 键和值，核心/扩展 schema 和动态成员均闭合；容器拒绝未知 chunk、不可达对象/二进制区间、非零空洞和尾部。纹理从像素重编码为内嵌 PNG 并按固定 chunk 白名单及 EOF 验收；STL 以严格语法和精确长度验收，二进制三角面的 attribute byte count 逐面固定为 `0x0000`。02 冻结白名单、报告和非零失败退出码，04 用逐类恶意反例验证“任一失败则整批不复制且目标目录哈希不变”。
- 正向回归固定使用一份所有三角面 attribute byte count 均为 `0x0000` 的合法二进制 STL；扫描报告、`exports`、UniApp 复制资产和页面下载文件以同一 SHA-256 串联，并由该文件继续完成 Bambu Studio 导入、尺寸回查与切片，防止实现以拒绝全部二进制 STL 的方式错误“修复”。
- 当前首版的 02 性能预算改由参数化低精度预览冻结；未来照片增量须以其新模型重新冻结 GLB 体积、三角面数、纹理、测试设备/浏览器、网络和加载耗时阈值。
- 每个 STL 由范本配置记录唯一的毫米参考包围盒；无实物尺寸时先选定目标打印高度，再按模型比例计算完整 `X/Y/Z`。Bambu Studio 验收同时核对导入尺寸，而不是只检查能否打开。

## 八、对研发档案的影响

- 当前 requirement/design 只把本材料作为未来照片增量的可行性参考；当前首版实现以 `2026-09-03-无照片参数化范本首版预研.md` 为路线依据。
- 本材料中 GLB/STL 格式、安全发布和 Bambu Studio 的已验证事实仍适用于当前首版；照片分级、照片低精度预览、纹理清理和照片来源标注不适用。
- 未来取得照片时先建立独立需求增量并重新评审，再决定是否读取 `source-photos`、替换模型及重设性能预算，不直接沿用当前首版结论。

## 九、局限、风险与后续验证

- 尚未覆盖: 用户未来照片的数量、清晰度、EXIF、视角分布、遮挡情况；这些项目不阻塞当前无照片首版。当前仍未覆盖具体拓竹打印机型号与可用打印空间。
- 风险:
  - 只有单一正面或严重遮挡时，背面与厚度只能设计补全。
  - 照片中的阴影、反光和周边物体可能形成错误几何，需要人工清理。
  - STL 不携带照片材质，也不天然表达单位；交付说明必须固定毫米口径并回查导入尺寸。
- 后续验证动作:
  1. 当前首版不读取 `source-photos`，不执行照片分级或照片预览。
  2. 未来用户取得照片并明确启动独立增量后，再生成只含匿名序号的视角分级和低精度预览；该结果只作为未来增量的设计门禁。
  3. 当前首版 04 自测仍需在用户实际 Bambu Studio 中导入并完成一次切片；具体耗材和打印参数由用户选择。
