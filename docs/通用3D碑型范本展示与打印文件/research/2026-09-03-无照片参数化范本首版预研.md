- 关联需求: [requirement.md](../requirement.md)

## 一、问题

当前没有照片时，能否先生成一个诚实标注、可网页展示且可导入 Bambu Studio 的通用无字石碑范本，并让以后照片修订复用同一页面和发布管线。

## 二、现状证据

- 仓库已安装 `three@0.183.2`，包含 `GLTFLoader`、`GLTFExporter` 和 `STLExporter`；网页无需新增三维运行时依赖。
- 03 实现期已从国内 npm 镜像安装 Khronos 官方 `gltf-validator@2.0.0-dev.3.10` 作为开发依赖；其包元数据指向 `KhronosGroup/glTF-Validator`，仅用于 Node 发布校验，不被 H5 页面导入。
- glTF/GLB 适合网页运行时传输；Bambu Studio 官方代码把 STL 列为支持的模型格式。格式依据沿用同目录既有预研中已锁定的官方证据。
- 固定二维闭合轮廓沿深度方向生成多个截面环，再对正背面三角化、对相邻环逐边连接，可以得到闭合实体；正背面使用缩小截面可形成可控倒角。
- 生成器只使用代码内固定数值，不读取照片、EXIF、纹理或外部模型，因此首版可以明确证明来源为参数化通用设计。

## 三、方案验证口径

首个范本采用以下冻结参数作为低精度原型和最终生成基线：

- 物理包围盒：宽 `140 mm`、深 `26 mm`、高 `160 mm`；STL 坐标为 `X=140 / Y=26 / Z=160 mm`。
- 正面轮廓：一体化宽底座、直立碑身和对称圆拱近似顶；不含文字、纹理或雕刻。
- 深度截面：`-13 / -10 / 10 / 13 mm` 四层，外侧截面缩小形成前后倒角。
- GLB 使用 Y 轴向上；STL 为切片习惯使用 Z 轴向上，两者形状和毫米尺寸一致但坐标轴映射不同。
- 材质只在 GLB 中使用固定灰石色 PBR 数值；STL 只包含三角面。

生成后必须以机械检查确认：包围盒、三角面有限值、退化/重复面、边邻接、方向一致、自交、连通壳、STL 精确长度、逐面 attribute byte count 为零、GLB 容器与闭合 JSON 白名单。GLB 和 STL 都从同一参数版本生成，并在轴向和单位归一后计算同一规范化三角面集合 `geometrySha256`；同包围盒不同形状必须失败。方案描述不能替代这些 03/04 阶段真实结果。

## 四、结论

- **可实现**：无需照片即可先完成通用无字范本、GLB 展示、STL 下载和安全发布闭环。
- **能力边界**：首版不是照片建模，也不代表任何真实石碑；页面和配置必须使用“参数化通用设计 / 非真实复刻”口径。
- **后续兼容**：以后拿到照片时，可复用同一匿名文件命名、配置接口、GLB 查看器、STL 下载和发布门禁，只替换或新增范本资产。
- **未在本阶段验证**：Bambu Studio 实际导入、尺寸回查和切片；这些仍是 04 自测真实环境门禁。

## 五、需求与设计影响

- 删除“照片目录为空阻塞 02”的条件，首版 `source-photos` 保持为空。
- 02 直接基于上述参数化原型冻结模型尺寸、无纹理策略和性能预算。
- 03 先写生成/安全发布固定样本测试，再实现生成器和页面；测试包含拓扑逐类反例、同包围盒不同几何，以及扫描全过后的复制/切换故障注入和重启恢复。
- 任何照片参考建模都作为后续需求增量重新评审，不能在首版中隐式改变来源标签。
