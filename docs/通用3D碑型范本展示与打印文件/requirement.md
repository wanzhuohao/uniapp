# 通用3D碑型范本展示与打印文件 · 需求文档（Spec）

- 日期: 2026-09-03
- 状态: 无照片首版范围已通过；02 设计进行中
- 提出人: 用户 / 当前 Codex 会话

## 背景

现有碑文系统已经具备个性化碑文录入和程序化 3D 预览，但该预览由基础几何体与碑文纹理组成，不能表达真实石碑外形，也不是可用于制造的三维实体模型。

用户当前没有可用于建模的照片，但希望先完成能够独立交付的部分。首版因此采用本地参数化方式制作一个不含姓名、日期或碑文内容的通用碑型范本，不宣称来自照片或真实石碑复刻；以后取得照片时，再作为独立增量修正外形。线下建模作为独立工作域放在 `D:\code\3d-models\stele`，而不是附属于 UniApp 页面目录；平台仅负责展示成品模型，并向需要打印的用户提供拓竹 Bambu Studio 可识别的模型文件。

## 目标

在 `D:\code\3d-models\stele` 中通过可复现的参数化几何制作至少一个无字通用石碑三维范本；在现有 UniApp H5 中新增独立范本页面展示 GLB 模型，并提供可由 Bambu Studio 导入和切片的 STL 文件下载。照片参考建模后置为未来增量，不阻塞首版。

## 用户场景

- 石雕从业者在独立石碑 3D 工作域中按固定尺寸参数生成可复用的无字通用碑型；以后有照片时可另行修订模型。
- 平台访客从首页进入独立的 3D 碑型范本页面，旋转、缩放并查看范本外观。
- 有打印需求的用户下载 STL，在自己的 Bambu Studio 中选择具体拓竹机型、材料和切片参数后打印。

## 功能需求

- **FR-01 独立线下建模工作域**：首版不使用照片输入；建模根目录固定为 `D:\code\3d-models\stele`，并分为 `source-photos/`（未来照片输入预留，首版保持为空）、`workspace/`（参数与中间文件）和 `exports/`（最终 GLB/STL）。建模处理不集成到 H5，也不新增照片上传、建模任务或云端重建接口。
- **FR-02 参数化通用建模**：首版使用版本化、可复现的轮廓和尺寸参数生成封闭无字实体，全部结构均标注为“通用设计”，不得标注为“照片可验证”或宣称真实复刻。以后基于照片的修订必须另行评审，不在首版暗中混入。
- **FR-03 通用无字范本**：建模结果不保留照片中的姓名、生卒日期、落款、名单及其他个性化碑文；碑体、底座和通用装饰可以保留或重建。
- **FR-04 双用途产物**：每个范本至少产出网页展示用 `GLB` 和拓竹切片用 `STL`；首版不强制生成 3MF。
- **FR-05 独立范本页面**：新增独立页面和入口，不替换、不改造现有个性化 `pages/stele/preview.vue` 业务语义。
- **FR-06 范本浏览**：页面支持至少一个范本，并采用可扩展配置组织名称、简介、缩略图、GLB 地址和 STL 地址；后续增加范本不需要重新设计页面结构。
- **FR-07 三维交互**：范本支持加载状态、自动取景、旋转、缩放、重置视角和全屏查看；加载失败时显示明确提示并允许重试。
- **FR-08 打印文件下载**：用户可从范本页面下载对应 STL；页面明确提示 STL 仍需在 Bambu Studio 中选择机型和切片参数，不直接发送打印机。
- **FR-09 原功能隔离**：新增页面不得读取或写入订单、碑文草稿和个性化碑文数据，也不得改变现有碑文新建、编辑、二维导出和 3D 预览链路。

## 非功能性需求

- **隐私**：首版不读取照片，`source-photos` 保持为空，也不得产生照片上传、对象存储或第三方建模请求。整个 `D:\code\3d-models\stele` 根目录及 `source-photos/workspace/exports` 三个子目录必须保持为非 Git、非 OneDrive/网盘自动同步目录；只有与通过报告中匿名文件名和 SHA-256 完全一致的文件才允许复制到 UniApp。以后取得照片时仍须另行执行原始照片只在本机、不得进入代码/档案/云端的安全门禁。
- **中间产物**：首版参数文件、中间网格和预览只能保存在上述非同步本地工作目录。交付验收时列出待清理清单；未经用户明确授权不删除任何工作域文件，用户授权后才执行定向清理并回查。
- **模型兼容**：GLB 应通过 glTF 2.0 格式校验；STL 应为封闭、法线一致、无自交的可切片实体。每个范本配置必须记录 STL 的参考包围盒 `X/Y/Z` 数值和毫米单位；无实物尺寸时，以建模者选定并记录的目标打印高度及模型比例计算该组唯一参考尺寸。
- **浏览器兼容**：至少覆盖当前项目用于验收的桌面 Chrome/Edge 和移动端 H5；WebGL 不可用或资源加载失败时必须可见失败，不得白屏。
- **资源与性能**：首版使用无纹理低面数几何；02 设计阶段必须基于参数化低精度预览冻结文件体积、三角面数、最大纹理尺寸、测试设备/浏览器、网络条件和加载耗时阈值，04 自测按同一组阈值判定，不得只以“最终能够显示”为通过。
- **资源释放**：页面卸载时释放动画帧、监听器、几何体、材质、纹理、控制器和渲染器，避免重复进入页面造成泄漏。
- **可维护性**：范本元数据与页面展示逻辑分离；首版至少交付一个范本，允许以后只追加资产和配置。
- **安全—命名与 JSON**：下载路径只暴露通用无字模型；不在前端资源中打包原始照片、带字纹理或线下建模中间文件。发布文件名使用区分大小写的完整正则 `^stele-template-([a-z0-9]+(?:-[a-z0-9]+)*)\.(glb|stl)$`，同一范本的 GLB、STL 和文件内可选名称必须使用同一匿名编号。`exports → UniApp` 前解析 GLB JSON chunk，并递归遍历所有对象键和字符串值，包括核心对象、`extensions` 及任意深度子对象：核心键必须属于固定的 glTF 2.0 schema；扩展必须按“扩展名 + 固定规范版本 + 允许成员 JSON Pointer”闭合；禁止自定义顶点属性语义和动态映射键。`extensionsUsed/Required` 必须与实际扩展载荷及 02 冻结白名单完全一致。所有 `extras`、`asset.generator`、`asset.copyright` 必须不存在；可选 `name` 必须不存在或严格匹配同一 `stele-template-<匿名编号>`。其余字符串只允许 glTF 2.0 核心规范固定版本/枚举/MIME 值，以及 02 按 JSON Pointer + 精确值冻结的扩展标识/规范枚举；白名单不得包含自由文本、路径或工具生成描述。未知键、未知值、未知扩展成员、声明与载荷不一致均默认失败。
- **安全—GLB 与纹理容器**：最终 GLB 必须为不含外链的单文件，任一 `buffers[].uri` 或 `images[].uri` 均直接失败。GLB 只允许一个 JSON chunk 和至多一个 BIN chunk；头部长度必须等于实际文件长度，拒绝未知 chunk、不可从选定场景及其有效依赖到达的 JSON 对象或 bufferView、重叠二进制区间、非零对齐空洞和尾随字节，规范允许的对齐填充只能使用规定字节。纹理必须从解码像素重编码为 `images[].bufferView` 引用的内嵌 PNG；PNG 必须校验签名、chunk 长度/CRC/顺序，仅允许 `IHDR/PLTE/IDAT/IEND/tRNS/sRGB/gAMA/cHRM/pHYs`，`IEND` 唯一且后面立即 EOF；发现 `eXIf/iTXt/tEXt/zTXt/iCCP`、未列 chunk 或尾随字节默认失败。任何无法归属到已验证 JSON、几何或纹理结构的字节默认失败。
- **安全—STL 容器**：二进制 STL 的 80 字节头必须全零或仅含 `stele-template-<匿名编号>`，文件总长度必须严格等于 `84 + 50 × 三角面数`，且每个 50 字节三角面记录末尾的 2 字节 attribute byte count 必须逐面等于 `0x0000`；通过报告记录“非零 attribute byte count 数量 = 0”，不允许借该字段存放颜色或其他扩展数据，也不允许尾随字节。ASCII STL 必须通过完整语法解析，首行 `solid` 与末行 `endsolid` 名称均严格匹配同一匿名编号且两者一致，末行后立即 EOF，不允许注释、额外对象或尾随内容。无法无歧义判定格式或不满足任一条件时默认失败。
- **安全—门禁事务**：02 设计必须冻结扫描器输入根、glTF 核心 schema 版本、每个允许扩展的规范版本/成员路径/精确值、报告 JSON schema、工具版本、白名单版本与 SHA-256、成功/失败退出码；发布以“整批扫描全部通过后才复制”为原子边界。通过报告至少绑定匿名相对文件名、文件 SHA-256、白名单哈希和各检查计数；任一失败、未知项、报告缺失或哈希不匹配时返回非零且 UniApp 目标目录保持字节级不变，不允许先复制后补扫。

## 验收标准

- [ ] **AC-01** 在未改动现有个性化 3D 预览业务语义的前提下，可从平台入口进入独立的“3D 碑型范本”页面并正常返回。

- [ ] **AC-04** 展示用 GLB 通过 glTF 2.0 校验，并在桌面 Chrome/Edge 与至少一个移动端 H5 环境完成真实加载验证。
- [ ] **AC-05** 下载所得 STL 必须是 AC-09 合法正例中“所有三角面 attribute byte count 均为 `0x0000`”且经报告绑定 SHA-256、复制和下载后 SHA-256 仍一致的同一份二进制 STL；发布报告还须证明有限坐标异常、退化面、重复面、边界边、超过两个邻面的非流形边、相邻面方向冲突、自交三角面对和额外连通壳计数均为 0。该文件能被 Bambu Studio 导入。验收记录 Bambu Studio 版本和所选拓竹机型，导入后的 `X/Y/Z` 与范本配置记录的毫米参考包围盒分别一致，允许误差为 `max(0.5 mm, 对应轴尺寸的 0.5%)`；随后能够完成切片，且没有阻断切片的空模型、破面、非流形错误。

- [ ] **AC-09** 02 已冻结安全条款要求的 schema/扩展/白名单/报告/退出码/原子复制契约；04 的合法批次必须包含一份所有三角面 attribute byte count 均为 `0x0000` 的二进制 STL，证明报告中非零计数为 0、全部 AC-05 拓扑失败计数为 0、批次通过、退出码为 0、复制成功，且报告、`exports` 源文件、UniApp 复制文件和页面下载文件的 SHA-256 全部一致；随后用该同一文件完成 AC-05。GLB 与 STL 必须绑定同一参数版本，并分别解析为三角面后归一到物理坐标 `X=宽/Y=深/Z=高` 和毫米单位：每个坐标四舍五入到整数微米、每个三角面内三点按字典序排序、所有三角面再按字典序排序，以 UTF-8 行文本计算 `geometrySha256`；两种格式摘要和规范化包围盒必须完全一致。再分别使用“未知 JSON 键或字符串、自定义属性键、未知/未声明/声明不一致扩展、外链 URI、未知 GLB chunk、不可达对象或 bufferView、非零空洞或尾部、PNG 文本/EXIF/ICC/未知 chunk/尾部、STL 非匿名名称/长度不符/二进制三角面 attribute byte count 非 `0x0000`/尾部、有限坐标异常/退化面/重复面/边界边/非流形边/方向冲突/自交/额外连通壳、同包围盒但不同几何、批次中一件扫描失败、扫描全过后复制第 N 件失败、提交切换前中断、目标目录切换失败”反例，逐项证明报告失败计数非 0、退出码非 0 且 UniApp 旧目标目录前后哈希完全不变；进程重启后的恢复动作也不得把暂存目录当成已发布目录。发布文件名必须完整匹配 `^stele-template-([a-z0-9]+(?:-[a-z0-9]+)*)\.(glb|stl)$`；合法报告中未知键、未知值、未知扩展、外链、不可达对象/字节、未列 PNG chunk、容器尾部、STL 结构、拓扑、自交、额外壳和非零 attribute byte count 失败计数均为 0。复制后再检查 H5 构建产物和网络请求，确认没有照片资源、带字纹理、个人碑文内容或新增照片上传/建模接口。
- [ ] **AC-10** 在范本配置中追加第二条本地测试数据后，页面无需修改核心渲染逻辑即可切换模型；测试数据不进入最终交付资产。

- [ ] **AC-13** 02 设计记录首个模型对应的 GLB 文件体积、三角面数、最大纹理尺寸、指定测试设备/浏览器、网络条件与加载耗时上限；04 在相同口径下逐项实测且全部不超过冻结阈值，失败时不得以“最终显示成功”替代性能验收。

## 边界 / 非目标

- 不在网页、小程序或云函数中实现照片上传和自动建模。
- 不把线下建模工程建立在 `uniapp/pages`、`uniapp/static` 或其他页面代码目录下；UniApp 只接收审核后的通用无字发布资产。
- 首版不等待、读取或要求用户提供照片；以后照片建模作为独立增量。
- 不把任何照片移入云同步目录，不使用必须上传素材的云建模服务；未经用户明确授权不删除任何工作域文件。
- 不承诺首版模型与任何真实石碑的轮廓、尺寸或雕刻一致。
- 不生成个性化碑文，不把当前碑文表单内容刻入范本。
- 不替换现有 `pages/stele/preview.vue`，不改变订单或碑文数据结构。
- 不对接拓竹打印机、不远程启动打印、不管理打印队列。
- 不预生成特定机型、喷嘴、耗材或层高对应的 G-code；这些参数由用户在 Bambu Studio 中选择。
- 未提供实物尺寸时，不承诺一比一还原；范本采用记录明确的参考尺寸，用户可在 Bambu Studio 中缩放。
- 首版不强制交付 3MF、STEP、OBJ 或建模中间工程文件。
