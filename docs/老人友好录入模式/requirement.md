## 当前有效需求（2026-09-10）

- 不提供独立老人模式、七步页面、语音、OCR、逐步确认或父母完整日期的额外公历核对。
- 手机新建页沿用“基本信息 → 名单 → 预览”三阶段。名单阶段固定显示只含小字的实时预览；最终阶段显示完整碑面。
- 电脑详情页不显示小字浮窗，但与手机页一样提供“自动规整 / 撤销整理”，并保留原完整碑面预览和拖动排序。
- 用户可把名单先在一排内按任意顺序录入，再一键按现有辈分/支系顺序规整并按录入先后匹配夫妻；空白姓名也是有效占位，不能被过滤、补人或前移。
- 自动规整可拆成多排；规整后允许人工拖动。只有在规整后尚未继续编辑或拖动时可撤销，避免旧快照覆盖新内容。
- 小字预览和保存必须严格使用名单当前实际分排；生成阶段不得再把相邻夫妻排隐式合并。撤销后预览和保存载荷必须恢复原分排。
- 订单管理员口令返回 401 时应立即允许重新输入；只有接口成功才缓存口令。取消、网络失败或服务失败后，下次操作仍可重新输入，写请求不得因结果未知而自动重放。

## 以下为已取消方案的历史需求

## 背景

现有碑文新建页和详情页已经覆盖父母姓名、生卒日期、立碑日期、横批、名单、预览、质检与保存，但主要依赖小字号表单、键盘输入、下拉选择和拖拽排序。对视力下降、手指精细操作困难、不熟悉手机键盘或只掌握旧碑照片的老人而言，录入成本和误操作风险较高。

项目已经具备可复用基础：两页共同使用 `useOrderForm()`，保存前统一生成 `SavePayload`；已有本地模板、草稿、预览、质检和结构化文本解析能力。本需求应在不改变现有订单保存契约的前提下，为新增和详情编辑提供可选的老人友好录入路径，并保证增强能力不可用时仍能完成手工录入。

## 目标

在 `pages/stele/index.vue` 与 `pages/stele/detail.vue` 提供醒目的“老人友好录入”入口，通过大字单列、分段填写、最终统一确认、可选语音、朗读回放、照片 OCR 候选、低置信度提醒、常用模板、易用日期选择和小字实时预览，降低手机端碑文录入门槛；所有识别结果必须经用户确认后才写入正式表单，现有普通模式和订单数据契约保持兼容。

## 用户场景

1. 老人在手机上新建碑文，按“类型 → 父/母姓名 → 生卒日期 → 横批 → 立碑日期 → 名单 → 总确认”的七步顺序逐步填写，不需要理解左右分栏、复杂表单或拖拽。
2. 老人或家属在详情页修改已有订单，切入老人模式后仍能看到已保存内容；各步骤直接修改并前后切换，只在最后总览时统一确认并保存。
3. 用户不熟悉键盘时，点击当前段的语音按钮口述姓名、日期或名单；系统只生成当前段候选，用户通过“大字确认 / 重说 / 手改”决定是否应用。
4. 用户持有旧碑照片时，从相册选择或调用后置摄像头拍照；系统在本机生成 OCR 候选并标出不确定内容，用户逐段核对，不自动覆盖订单。
5. 用户眼睛看不清或担心输错时，点击“朗读本段”听取当前确认文本；不支持朗读的浏览器仍可正常看字和手工输入。
6. 用户只记得年份、使用农历日期或常在清明立碑时，可以通过大按钮和分列日期选择器明确选择，而不是依赖自由文本格式。

## 功能需求

### FR-01 模式入口与兼容

- 新建页和详情页首屏均提供持续可见、文案明确的“老人友好录入”按钮或模式开关；普通模式仍为现有用户可选路径。
- 切换模式不得清空、重置或重复保存当前表单；从详情页进入时必须保留已加载订单，从草稿或复制入口进入时必须沿用现有来源数据。
- 老人模式只改变录入与确认交互，最终仍通过现有 `useOrderForm()`、质检和保存链路生成订单，不新增老人专用订单结构。

### FR-02 大字逐段录入

- 老人模式采用单列分段流程，一屏聚焦一个主题：类型、父/母姓名、生卒、横批、立碑日期、名单、总确认。
- 每段展示当前进度、返回和下一步；步骤切换不要求点击“本步核对无误”，允许随时返回修改且内容不得丢失。
- 所有关键操作都提供单击/轻触方式；名单排序不得只依赖拖拽，至少提供“上移 / 下移”或等效按钮。
- 名单步骤在编辑称谓、姓名、排数和顺序时，必须同步展示与最终碑文共用生成逻辑的实时小字排版预览；预览可随输入立即更新，不要求先进入总确认。
- 正文默认字号不小于 20 CSS px，关键确认文本不小于 24 CSS px，主要触控目标不小于 48×48 CSS px，320 CSS px 宽度下除碑文预览外不得要求双向滚动。

### FR-03 分段语音输入

- 每个适合口述的段落在运行时**能够证明音频仅在设备本地处理**时，提供“开始说话 / 停止”按钮，默认识别语言为普通话 `zh-CN`；录音状态必须同时用文字、颜色以外的图标/动画和停止按钮表达。
- “能够证明本地处理”必须同时满足：浏览器提供端侧识别能力探测；`zh-CN` 本地语言包已可用或在用户单独同意后完成下载；每次识别实例显式请求本地处理。任一条件无法确认时不启动应用内语音识别，只保留手工输入。若提示系统键盘听写，必须同时注明“该能力由操作系统或输入法厂商提供，不受本应用端侧处理、不出网和不留存承诺覆盖；是否联网以系统设置与输入法厂商说明为准”，不得描述为等价的本地语音能力。
- 第一次使用前说明将申请麦克风权限、语音仅在本机处理、是否需要下载语言包、音频与识别文本不保留以及取消方式；用户独立同意后才申请麦克风或下载语言包。首版禁止回退到可能把音频发送给浏览器厂商在线服务的远端 Web Speech 模式。
- 识别中间结果可展示，但不得直接写入正式表单；最终候选只属于当前段，不得跨段修改其他字段。
- 不支持、拒绝权限、无网络、超时、无语音或识别失败时，显示可理解原因并保留当前内容，立即提供手工输入；语音能力不得成为完成录入的前置条件。
- 每次启动必须由用户主动点击触发；离开当前段、切换模式、页面隐藏或点击停止时必须结束识别，不允许后台持续收音。

### FR-04 碑文照片 OCR 候选

- 提供“从相册选择 / 拍一张碑文”入口，首版优先采用文件选择器与 `capture="environment"` 提示，不直接长期持有摄像头视频流；拍照提示不生效时必须允许从相册或文件选择。
- 只接受魔数与 MIME 同时匹配的 JPEG、PNG、WebP 静态图片，单文件不超过 15 MiB，图像宽/高均不超过 8000 px 且总像素不超过 2400 万；明确拒绝 SVG、GIF、HEIC、未知格式、魔数不符、损坏或超限图片。正式创建大位图前先在 Worker 或等效非阻塞路径读取头部尺寸并校验，解码后立即等比缩放至长边不超过 2400 px 再进入 OCR；运行环境无法安全预检或缩放时拒绝该图并回退手填，不尝试冒险解码。
- 首版采用浏览器本地 OCR 试用方案，图片和 OCR 原文默认不上传云端、不写入订单、不写入日志、不持久保存；完成、取消或离开页面后释放图片引用和识别 Worker。
- OCR 必须异步运行并显示进度、取消和失败回退；相关代码与中文模型延迟加载，不得阻塞普通模式和老人模式首屏。
- OCR 输出先进入独立的“候选文字”区域，不直接推断并覆盖父母、日期或名单。系统可基于现有结构化文本解析器给出字段建议，但解析必须作用于克隆数据、候选 DTO 或差异映射，禁止把正式 `OrderForm` 直接传给会修改对象的解析器；每个建议必须单独确认后才写入正式表单。
- 首版 OCR 发布前使用至少 20 张经授权并脱敏的代表性碑文照片验证，其中至少 10 张为“清晰样本”，其余覆盖倾斜、反光、竖排、不同字体和风化。清晰样本须同时满足：目标文字区域完整、裁剪后长边不低于 1600 px、无明显运动模糊/遮挡/强反光、主要文字高度不低于 24 px。
- **评估前冻结**：在运行任何评估图片前生成只读评估 manifest，固定协议版本、样本编号/分层及图片哈希、真值哈希与字段清单、OCR应用构建、Tesseract.js/Worker/中文模型版本及模型哈希、预处理和版面参数、三台测试设备与 OS/浏览器版本、超时值、统计脚本版本，以及 0～100 置信度量表上的低置信度阈值 `<80`；同时冻结下述七项安全检查及预期证据路径。不得看过 OCR 与真值对比后调阈值或参数；任一冻结项变化必须生成新协议版本并从全部样本重跑，不能把两版结果混算。运行结束另生成不可变结果 manifest，引用评估 manifest 哈希，记录每项安全布尔结果、证据索引和逐项指标；不得回写原评估 manifest。
- **真值与准确率**：两名标注人独立转写后逐字复核达成一致；比较前仅执行 Unicode NFKC 规范化并移除 Unicode 空白，不做简繁、异体字、同音字或标点替换。字符错误率 `CER = 目标集合内 Levenshtein 编辑距离之和 / 同一集合真值字符数`，字符准确率为 `max(0, 1-CER)`；用同一公式分别计算全部样本与清晰样本的字符准确率，发布门禁使用清晰样本值。每张照片在评估前标注实际可见的父/母姓名、父/母生卒日期、立碑日期、横批和名单姓名项；不可见或原碑不存在的字段在 manifest 中预先排除并写原因。姓名、日期分别在全体冻结样本上按规范化后字段完全相等计算，OCR 缺失计错误；样本集必须各含至少 20 个姓名字段和 20 个日期字段，否则属于必需指标缺失。
- **不确定内容指标**：一个字段只要其映射到的任一最小可用 OCR 单元置信度 `<80` 就将整个字段标记待核对；引擎没有可映射置信度、字符/字段映射失败或字段输出为空时也标记待核对。错误暴露召回率为“识别错误且已标记待核对的字段数 ÷ 全部识别错误字段数”，分母为 0 时记 100%；误标率为“识别正确但被标记待核对的字段数 ÷ 全部识别正确字段数”，分母为 0 时记 100%。姓名和日期共同按字段微平均，不按照片平均。
- **非空结果率**：先对每张样本在每台冻结设备上的执行结果分别计算 `device_nonempty`：只有完成 OCR 与字段映射后，至少一个预先标注的目标字段经 NFKC 规范化、移除 Unicode 空白后仍包含至少一个 Unicode 字母或数字（正则语义 `\p{L}|\p{N}`）才为 `true`。只有空白/标点、整图有文字但所有目标字段为空、字段映射失败、OCR加载/解码/执行超时或崩溃均为 `false`；性能/准确率正式批次中的人工或系统取消也为 `false` 并按超时计时。每张样本的 `sample_nonempty = Android Chrome.device_nonempty AND iOS Safari.device_nonempty AND 微信内置浏览器.device_nonempty`，任一设备结果缺失同样按 `false`；全部样本非空结果率为 `sample_nonempty=true 的样本数 ÷ 评估 manifest 中全部有效样本数`。结果 manifest 必须保存三台设备各自的布尔值和 `evidence_id`、派生的 `sample_nonempty` 及公式版本。专门验证取消能力的独立用例不进入准确率/性能样本分母，只进入安全检查。
- **性能口径**：预先指定 Android Chrome、iOS Safari、微信内置浏览器各一台真实设备，并在 manifest 记录设备型号、OS/浏览器版本、同一 HTTPS 测试源以及统一的 `20 Mbps` 下行、`5 Mbps` 上行、`40 ms` 往返时延网络整形配置；每张样本在每台设备上执行一次冷启动识别，每次先清除本应用 OCR HTTP 缓存并重开页面。计时从用户在已选图状态点击“开始识别”到候选文字或终态错误完整渲染，包含懒加载脚本/自托管模型的首次网络下载、Worker 初始化、预处理和 OCR；超时/崩溃记 40001 ms 且结果为空。所有设备合并值及每台设备值均用 nearest-rank：升序排列 N 个耗时，取第 `ceil(0.95×N)` 个；门禁 P95 取“合并 P95 与三台设备各自 P95”的最大值，不做设备均值。
- **安全边界布尔清单**：结果 manifest 必须逐项记录 `(pass/fail, evidence_id)`，七项全部为 `pass` 才算通过；任一缺值按 `fail`。固定七项为：S1 在选图前完成 OCR 独立告知/同意且拒绝不触发文件选择；S2 只接收上述格式/大小/像素边界并安全预检、缩放；S3 网络证据证明除同源脚本/Worker/模型静态资源外没有上传图片、OCR文本或可还原数据；S4 订单、草稿、模板、localStorage/IndexedDB/Cache Storage 与应用日志均无图片、OCR原文、候选和置信度；S5 完成、取消、失败、切段/模式、页面隐藏/离开后均释放 Worker、Object URL、图片缓冲与任务引用；S6 前端产物及请求中无第三方密钥；S7 每张样本均有关联的有效授权/来源凭证且证据留存、撤回、到期和销毁符合下述规则。证据索引必须指向受控目录中的网络导出、存储/日志扫描、资源计数、授权台账或测试记录，不得只写人工结论。
- **唯一判定顺序**：先判“下线”——任一冻结项、必需逐样本证据或指标缺失，S1～S7 任一不为 `pass`，任一设备不能取消并释放 Worker/图片引用，清晰样本字符准确率 `<70%`，全部样本非空结果率 `<80%`，或门禁 P95 `>40 秒`；未下线且同时满足清晰样本字符准确率 `≥85%`、姓名与日期字段完全匹配率分别 `≥95%`、错误暴露召回率 `≥90%`、误标率 `≤50%`、门禁 P95 `≤20 秒`时判“正式辅助入口”；其余情况唯一判“试用”，所有输出整段标记待核对。按此先后短路执行，不允许同一评估同时命中多个结果；OCR 判为试用或下线均不影响其余老人模式交付。
- **样本与证据治理**：样本只能来自合成/明确可合法使用的公开材料或取得用途授权的照片；采集后去除 EXIF，并遮盖人脸、车牌、位置和无关个人信息。Git 仓库、应用日志和流程文档之外的受控本机目录可在评估期暂存原图、规范化真值、OCR 原始/规范化输出、字段映射、逐单元置信度、待核对掩码、逐次耗时、计算清单与冻结/结果 manifest，仅“样本管理员”和“04 独立复算人”可访问。04 最终核验必须用这些逐样本证据独立复算后再出聚合结论；完成后 7 天内删除原图、真值、图片/真值哈希和全部逐样本结果，除非需求方另批期限。流程档案长期只保留协议、应用构建及模型的版本/哈希、非敏感样本编号和分层、聚合指标、唯一判定与销毁回查记录，不保留图片或真值哈希。
- **授权/来源证明治理**：需求方在采集前指定一名样本管理员；未指定则不得征集真实照片，只能使用合成或许可证明确的公开材料。受控授权台账每项只记录随机 `authorization_id`、样本编号、来源类别、授权/许可证日期、允许用途（仅本需求本地 OCR 评估）、到期日、撤回渠道、授权证明受控路径和状态；真实授权人的姓名/联系方式/签字或录音只存在授权证明中，不写 manifest、Git、日志或流程档案。台账和证明仅样本管理员与 04 独立复算人可访问，保留至 04 核验后 180 天；到期后 7 天内删除并留操作记录。授权人撤回时，样本管理员须在 1 个工作日内停止使用、24 小时内删除对应原图/真值/逐样本结果并使旧结果失效；若样本数量或分层不再达标则整批重新评估。长期档案只保留不可反推个人的 `authorization_id`、来源类别、授权/撤回/到期日期、删除状态和操作者角色，不保留授权人身份、联系方式或证明文件；撤回/到期操作记录同样在 180 天期满后 7 天内删除。

### FR-05 大字确认与低置信度处理

- 语音或 OCR 产生候选后，统一显示“大字候选 + 来源 + 待确认状态 + 正确 / 重说或重识别 / 手改”操作。
- 有置信度信息时按段或字符标出低置信度内容；无法获得字符级置信度时，整段标记“识别结果待核对”，不得伪造精确分数。
- 低置信度内容不能通过自动下一步隐式确认；用户必须明确选择“已核对无误”或修改为确认值。
- 只有已确认值才能写入 `OrderForm`。候选内容、置信度和识别中状态均为临时 UI 状态，不进入订单、模板或草稿，避免未确认数据被普通保存链路带走。
- 日期候选的“确认”必须经过唯一的原子日期写入接口，同时更新当前 `OrderForm` 字段与现有日期引用状态（或在 02 设计中收敛成单一事实源）；不得直接只改其中一份。确认后立即生成的 `buildSavePayload()` 必须与屏幕确认值逐字段一致，不能被保存前的 `syncDatesToForm()` 用旧值覆盖。

### FR-06 朗读回放

- 当前正式表单中的姓名、日期、横批、名单和总确认均提供“朗读本段 / 停止朗读”按钮；朗读内容必须与屏幕展示一致，当前段结束后不自动连续朗读下一段。
- 朗读必须由用户点击触发；切换段落、切换模式、页面隐藏或离开页面时停止并清空队列。
- 浏览器没有 `speechSynthesis` 或没有可用中文语音时，隐藏或禁用朗读按钮并给出手工核对提示，不阻塞录入和保存。

### FR-07 常用模板

- 老人模式复用现有本机模板数据与白名单，不新建另一套模板存储；模板不得包含客户标识、备注、语音、照片、OCR 原文或识别置信度。
- 以大卡片展示常用模板的名称、适用类型和“预览后生成候选”按钮；操作后只生成临时字段候选，每项都必须单独采用或放弃，采用前不写入 `OrderForm`。处理完候选后回到分段编辑流程，不能整份模板直接覆盖或直接保存。
- 至少提供常用横批快捷选择（首批包括“永垂千古”，其余文案由需求方在 02 设计确认），并允许继续手工输入。

### FR-08 易用日期选择

- 父母生卒日期支持“完整日期 / 只记得年份 / 不知道”三种明确状态；立碑日期支持“清明节 / 公历自定义 / 农历自定义”。
- 完整日期使用大尺寸年、月、日选择控件；年份允许直接输入和快速增减。选择“只记得年份”时只保存年份且不提示为输入错误；选择“不知道”时清空该日期并在确认页显示“未填写”。
- 父母完整生卒日期沿用现有年月日数据和质检，不增加“按公历核对”声明、按钮或保存门禁；已加载的完整日期也不要求用户重新确认历法。
- 农历仅表示所填年月日的历法属性，首版不隐式换算为公历；日期展示、预览和保存语义必须与现有 `dateShowLunar`、`libei` 契约一致。
- 公历完整日期必须按真实月份天数和闰年规则校验；农历自定义在未引入具体历法转换库时只校验月为 1～12、日为 1～30，并明确标记“农历”。日期不可能（如公历 2 月 30 日）、生卒倒置或语音/OCR 无法确定历法时必须在确认前提示，不得静默纠正成另一日期。

### FR-09 总确认、质检与保存

- 提交前以大字汇总所有正式表单段落，显示“已填写 / 未填写 / 需修改”；每段可直接返回编辑。
- 分段流程只保留最后一个“确认并保存”动作，不设置每步确认按钮，也不以步骤确认状态或父母完整日期历法声明阻断保存。
- 继续执行现有必填、名单完整性、重复名单、日期和容量质检；老人模式不得绕过现有保存防重入和客户标识流程。
- 存在未处理的语音、OCR 或模板候选时必须提示用户逐项采用或放弃；所有候选处理完后才能保存。正式表单通过质检后，保存载荷与普通模式同构。
- 保存成功、失败、草稿保留和重试均用大字、明确动作说明，不只依赖短暂 Toast。

### FR-10 隐私、权限与诊断

- 页面首次使用语音或 OCR 前分别展示用途、处理位置、网络边界、保留时间和取消方式；两个授权说明不能互相替代。语音说明须明确端侧处理、可选语言包下载、麦克风仅在当前段使用和音频/文本不保留；OCR 说明须在选图前明确图片仅本机处理、不上传/不持久化/不记日志及退出即释放。每项都提供独立的“同意继续 / 暂不使用”，拒绝后不得弹出对应系统权限或启动处理，现有表单与手工流程保持不变。
- 诊断只记录能力可用性、错误码、阶段和耗时，不记录姓名、日期、名单、识别文本、音频、照片内容或可还原业务数据。
- 禁止在前端放置云 OCR、云语音或其他厂商密钥。后续若引入云服务，必须另行完成供应商、成本、后端代理、数据保留、隐私说明和外部写授权评审。

## 非功能性需求

### 可访问性与易用性

- 对齐 WCAG 2.2 AA 的最低方向：普通文本对比度至少 4.5:1，大文本至少 3:1；320 CSS px 宽度下内容可重排；任何拖拽功能都有单击替代。
- 老人模式不以颜色作为唯一状态提示，关键按钮使用动词短句和常见图标，错误信息同时说明“发生了什么、如何继续”。
- 系统字体放大到 200% 时，除碑文视觉预览外，不丢失输入、确认、返回和保存能力。

### 兼容性与降级

- 核心大字分段、手工输入、模板、日期、确认和保存应覆盖现有 H5 可运行环境，并在 Android Chrome 近两个大版本、iOS Safari 近两个大版本和当前微信内置浏览器各选一台代表设备验证。
- `SpeechRecognition`、本地语音包、`capture` 提示和中文语音均采用运行时功能探测；任何探测失败都按本 Spec 的手工路径降级，不用浏览器名称硬编码能力。
- 语音功能探测必须验证端侧处理能力而不只是验证 `SpeechRecognition` 对象存在；实验性的本地语言包探测/安装接口不存在、报错或结果不确定时按“不支持应用内语音”处理。
- 本地 OCR 依赖 WebAssembly 与 Worker；不满足能力、格式、15 MiB、8000 px 单边、2400 万像素、内存或时间门限时拒绝或停止任务，释放资源并保留表单。

### 性能与资源

- 老人模式基础 UI 不引入新的首屏远程调用。语音、OCR 代码和中文 OCR 模型均按需加载。
- OCR 启动后 1 秒内显示确定的加载/识别状态；代表性设备上单张裁剪后图片目标在 20 秒内返回候选，超时可取消并回退手填。该目标须在 02 技术验证中实测，未达标则 OCR 不作为首版承诺能力。
- OCR 在 Worker 中执行，处理期间页面的停止、返回和手工输入控件保持可响应；连续处理结束后不遗留活动 Worker、图片 URL、麦克风或朗读队列。

### 安全与隐私

- 首版新增能力不上传照片、不保存音频，不使用远端语音识别或新增外部 SaaS；现有 HTTPS 托管继续作为媒体权限前提。
- 本地模板、草稿和识别临时状态严格分离；未确认候选不持久化。
- 弱网、拒绝权限和增强能力异常不得导致已确认表单丢失、订单重复保存或后台持续采集。

### 成本边界

- 首版优先零新增按次 API 费用：大字交互、朗读、模板、日期和本地 OCR 使用浏览器/本机能力；成本主要是研发、OCR 模型流量和终端 CPU/内存。
- 应用内语音仅在可证明端侧处理时启用，无按次 API 费用，但实验性能力、语言包流量和兼容测试会增加研发成本；无法证明端侧处理时直接降级，不借用浏览器厂商远端识别。
- 云 OCR/云语音不在首版范围；若后续启用，费用、免费额度耗尽后的自动计费、密钥托管和数据合规必须单独确认。

## 需求确认记录

- 技术可行性: 有条件可行。模式切换、大字逐段、模板、日期、朗读与确认层可复用现有 Vue 3 / `useOrderForm()`；语音识别仅在浏览器能证明 `zh-CN` 端侧处理时渐进启用，否则手工降级；本地 OCR 可运行在浏览器 Worker，但对碑刻/书法/竖排照片的准确率必须通过可复现样本门禁，不能自动入表。依据见[技术预研](research/2026-09-07-老人友好录入能力可行性.md)。
- 开发周期: 单人估算，排除 OCR 的核心老人模式约 6～9 人日；包含本地 OCR 试用、20 张样本评估和三类移动浏览器回归约 10～15 人日。若改为云 OCR/云语音，另增加约 5～8 人日及供应商、隐私和计费审批，不在本需求首版内。估算将在 02 设计按组件拆分和样本准备情况校正。
- 需求合理性: 合理。老人用户的主要障碍是视觉、精细操作、键盘和错误确认；保留普通模式并把识别限制为“候选先确认”可获得主要收益，同时砍掉高风险的一键自动填表、自动保存和首版云服务，避免误刻碑文与隐私/费用失控。
- 确认人 / 日期: 主 Agent 初判 / 2026-09-07；待用户确认 01 后生效。
