## 一、问题与待决策项

1. 当前 UniApp H5 能否在新建页和详情页复用同一表单实现老人模式，而不改订单结构？
2. 手机浏览器分段语音输入的权限、隐私和兼容性是否足以成为核心录入方式？
3. 碑文照片能否在浏览器本地 OCR，并以低置信度候选方式安全辅助录入？
4. 大字逐段确认、朗读、常用模板和日期选择是否已有可复用基础？
5. 首版怎样控制开发成本、运行成本、终端资源和隐私风险？

这些问题直接决定首版是否需要新增云服务、订单字段、后端密钥代理，以及语音/OCR是否可以纳入强制验收路径。

## 二、假设与判据

- 当前假设 A: 老人模式只是一层录入/确认 UI，确认后写入现有 `OrderForm`，因此保存协议可保持不变。
- 当前假设 B: 浏览器语音识别兼容性不足，必须功能探测并保留手工输入；朗读兼容性显著更好。
- 当前假设 C: Tesseract.js 可在浏览器 Worker 运行中文 OCR，但通用印刷体模型不能证明适用于风化、反光、竖排或书法碑刻。
- 当前假设 D: 低置信度状态应停留在候选层，不能进入草稿、模板和订单。

通过判据：存在不改变订单契约的最小实现路径；每项增强能力有明确权限、隐私、成本、兼容性和失败回退；无前端密钥；未确认识别结果绝不进入保存载荷。

失败判据：核心流程依赖非基线浏览器 API、必须上传敏感图片/音频、需要在前端放密钥、或 OCR 无法提供可核对候选且会静默覆盖订单。

### 6.2 外部能力证据

| 能力 | 权威事实 | 权限 / 隐私 | 兼容性 | 成本 | 可行性结论 |
|---|---|---|---|---|---|
| Web Speech 语音识别 | [MDN SpeechRecognition](https://developer.mozilla.org/en-US/docs/Web/API/SpeechRecognition) 标记为 Limited availability；默认实现可能使用服务器端识别。MDN 同页记录了实验性的 `processLocally` 以及 `available()` / `install()` 本地语言包能力 | 需要用户主动同意麦克风；首版只有能证明 `zh-CN` 端侧处理时才启动。语言包下载可联网，但识别音频不得发送给第三方 | 不能作为 Baseline；端侧处理与语言包接口仍为实验能力，任一接口缺失或状态不确定即降级手填 | 无项目侧按次 API 账单，但有语言包流量、设备资源和兼容测试成本 | 高条件可行：只作端侧逐段增强；禁止回退到浏览器厂商远端识别 |
| 麦克风/摄像头流 | [MDN getUserMedia](https://developer.mozilla.org/en-US/docs/Web/API/MediaDevices/getUserMedia) 要求 HTTPS、安全上下文和用户许可，且浏览器必须显示采集指示；iframe 还受 Permissions Policy 约束 | 权限必须按来源授予，用户可拒绝；页面需在离开/停止时关闭轨道 | API 本身广泛可用，但本需求不需要长期摄像头流 | 无按次费用；有隐私与生命周期开发成本 | 语音若自行采流须严格关闭；照片首版不直接用视频流 |
| 文件拍照提示 | [MDN capture](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Attributes/capture) 说明它只用于 file input 且为 Limited availability，`environment` 只是后置摄像头提示 | 应用只接收用户最终选择的文件，不持有持续摄像头流；系统仍可能展示相机/文件选择提示 | 部分浏览器忽略 `capture`，必须保留相册/文件选择 | 无按次费用 | 可行但需降级，不能把“直接打开后置相机”写成跨浏览器保证 |
| 朗读 | [MDN SpeechSynthesis.speak](https://developer.mozilla.org/en-US/docs/Web/API/SpeechSynthesis/speak) 为 Baseline / Widely available | 仅输出声音，不需麦克风；文本仍不应写日志 | 跨设备广泛可用，但中文音色由系统/浏览器提供，可能缺失 | 无按次费用 | 高可行；按钮触发、可停止，无中文音色时降级 |
| 浏览器本地 OCR | [Tesseract.js 官方仓库](https://github.com/naptha/tesseract.js) 通过 WebAssembly 把 Tesseract 带到浏览器/Node，支持 100+ 语言、旋转预处理和粒度化输出；[Tesseract 官方模型](https://tesseract-ocr.github.io/tessdoc/Data-Files.html) 提供 `chi_sim` / `chi_tra` | 模型和图片可完全留在浏览器；若使用 CDN 拉 Worker/模型仍会产生第三方请求，首版应自托管或明确固定来源 | 依赖 WebAssembly、Worker、内存和模型下载；旧设备需实测和超时回退 | 无每次调用费，但增加模型流量、终端 CPU/内存和研发测试成本 | 技术可行，但只适合本地候选试用 |
| 碑刻/书法 OCR 准确性 | [Tesseract.js FAQ](https://github.com/naptha/tesseract.js/blob/master/docs/faq.md) 明确模型建立在印刷文本假设上；Tesseract.js 本身不修改识别模型提升准确率 | 本地方案隐私更好，但无法用隐私优势替代准确率验证 | 风化、反光、竖排、书法与浮雕均超出“清晰印刷文本”理想条件 | 若定制训练会显著增加数据标注和研发成本 | 未经样本不能承诺生产级准确率；必须候选先确认并设置 20 图门禁 |

## 七、结论分层

### 已验证事实

1. 新建页和详情页已共享表单、预览、草稿、模板、质检和保存链路，订单结构不需要为老人模式新增字段。
2. 当前代码不存在语音/OCR依赖和页面入口，但存在可复用的结构化文本解析器。
3. 浏览器语音识别不是跨主流浏览器 Baseline，默认实现可能把音频发送给浏览器厂商在线服务；因此首版不能仅凭 API 存在就启用。
4. 浏览器朗读广泛可用；拍照 `capture` 只是有限兼容的 file input 提示。
5. Tesseract.js 能在浏览器通过 WebAssembly 工作并有中文模型，但官方同时限定其模型假设更接近印刷文本；本轮没有真实碑文照片证据。
6. 本地 OCR 与浏览器能力可避免新增按次 API 费用；云 OCR 有免费额度但会进入资源包/后付费和图片出网路径。

### 基于事实的推论

1. 最稳妥架构是“手工大字流程为核心，语音仅在端侧处理可证明时启用，OCR/TTS按能力渐进增强”，而不是按浏览器品牌写死功能。
2. 语音和 OCR 都应先写独立候选状态，确认后才调用现有表单更新；日期确认必须原子更新日期引用状态与 `OrderForm`，或先收敛为单一事实源，避免 `buildSavePayload()` 的保存前同步用旧引用覆盖确认值。
3. 现有结构化文本解析器能降低字段映射成本，但没有测试证据，02 必须先补解析器样例和不变量，再接语音/OCR。
4. 本地 OCR 首版应自托管 Worker/模型并懒加载；否则 CDN 请求会削弱“图片不出网”的隐私表述。
5. 老人模式不应只放大字号，还必须提供非拖拽排序、明确错误恢复、逐段确认和朗读停止，否则不能覆盖精细操作与认知负担。

### 最终决定

| 能力 | 首版定位 | 决定 |
|---|---|---|
| 模式入口、大字单列、逐段确认、非拖拽操作 | 核心 | 纳入，且在所有现有 H5 环境保留手工完成路径 |
| 朗读回放 | 核心增强 | 纳入，`speechSynthesis` 不可用时降级 |
| 常用模板、日期选择 | 核心 | 复用现有模板/日期契约，补老人交互和明确状态 |
| Web Speech 分段语音 | 条件增强 | 只有运行时可证明 `zh-CN` 端侧处理时才显示可启动入口；语言包下载需独立说明，无法证明时关闭并手填，不允许远端识别回退 |
| 本地照片 OCR | 受门禁增强 | 纳入 02 技术验证；按 Spec 的授权样本、CER、关键字段、错误暴露和 P95 三档门禁唯一决定“正式 / 试用 / 下线” |
| 低置信度 | 安全门禁 | 所有识别统一使用候选确认；无字符级置信度时整段待核对 |
| 云 OCR/云语音 | 非首版 | 不接入；若未来采用，重新评估供应商、费用、后端、隐私和授权 |

## 九、局限、风险与后续验证

- 尚未覆盖: 真实手机权限弹窗、微信 WebView 具体版本、中文系统音色、弱网、低内存设备、真实碑文照片准确率和 OCR 中文模型体积。
- 风险: 浏览器端侧语音与语言包接口覆盖率很低或策略变化，导致多数设备只有手工输入；Tesseract 对碑刻样本准确率低；OCR Worker/模型引发首屏或内存问题；本地模板只在当前浏览器设备可用。
- 后续验证动作:
  1. 02 优先使用合成/许可证明确的公开材料；征集真实照片前由需求方指定样本管理员，通过受控授权台账记录最小字段、用途、期限和撤回渠道。至少 20 张样本移除 EXIF、遮盖无关个人信息后存入 Git 与日志之外的受控本机目录；由两人独立转写并复核真值，在第一次评估前冻结样本/真值哈希、OCR构建/模型、置信度阈值、三台设备、安全 S1～S7 清单和统计脚本。
  2. 02 建立 Chrome Android、Safari iOS、微信 WebView 的无权限探测矩阵，单独验证端侧处理、`zh-CN` 语言包和失败关闭；真实麦克风/相机测试在 04 用户可见环境执行，网络面板不得出现音频外发。
  3. 02 对 Tesseract.js 自托管 `chi_sim`/方向模型做懒加载、Worker、取消、内存与冷启动耗时实验；按 Spec 在固定 `20 Mbps` 下行、`5 Mbps` 上行、`40 ms` RTT 网络整形下，于 Android Chrome、iOS Safari、微信内置浏览器清缓存逐图计时，用合并/单设备 nearest-rank P95 的最大值判定。
  4. 03/04 为语音/OCR候选不入表、克隆候选解析、切页停止、图片格式/15 MiB/8000 px/2400万像素边界、固定 `<80` 低置信度标记、真实公历日期、日期原子同步、仅年份状态和保存防重入补自动化与浏览器用例；04 使用逐样本证据独立复算非空率、聚合指标、安全布尔清单与唯一短路判定，其中样本非空固定为 Android Chrome、iOS Safari、微信内置浏览器三项 `device_nonempty` 的逻辑与，任一缺值按 `false`。
