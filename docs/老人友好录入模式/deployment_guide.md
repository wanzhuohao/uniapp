5. 在电脑详情页确认有自动规整/撤销、无小字浮窗，原完整碑面预览、拖动排序和保存仍可用。
6. 在订单列表页验证错误管理员口令可连续重新输入；取消后下次操作可再输入；正确口令能查询。生产口令只由用户在页面输入，不写入文档或测试数据。

## 构建

在 PowerShell 中为 HBuilderX CLI 设置本项目的 `UNI_INPUT_DIR`、`UNI_OUTPUT_DIR`、`UNI_PLATFORM=h5`、`NODE_ENV=production`、`UNI_HBUILDERX_PLUGINS` 和 `UNI_CLI_CONTEXT`，然后在 HBuilderX 的 `uniapp-cli-vite` 目录执行：

```powershell
node .\node_modules\@dcloudio\vite-plugin-uni\bin\uni.js build
```

输出目录为 `dist/`。旧七步方案 2026-09-07 的 34 文件和入口哈希已经失效，不能作为当前部署凭据；正式发布必须以最终源码重新构建后的文件数和哈希为准。

## 部署步骤

1. 备份当前线上完整 H5 静态目录和对应版本号。
2. 将本次 `dist/` 的完整内容作为一个不可变版本上传到现有静态托管位置，不混写旧版本目录；入口 HTML 与带哈希资源必须来自同一次构建。
3. 如现有托管流程支持测试/预发，先在该环境按“发布后冒烟”逐项验证；否则在生产切换后立即冒烟，任一关键项失败就回滚。
4. 冒烟通过后再按现有静态站点发布流程切换生产版本；本需求无需执行 DDL、配置刷新或后端服务重启。
5. 发布完成后保留上一稳定版本，直至观察期结束。

## 发布后冒烟

- 手机新建页只显示“基本信息 → 名单 → 预览”三阶段，不出现老人入口、七步流程、逐步确认或父母日期额外公历核对。
- 名单页的预览窗固定在可视区域，滚动名单时位置不随列表漂移；窗口只显示小字，可收起并调整字号；最终预览页显示完整碑面。
- 在一排内乱序输入子/媳、女/婿、孙辈、自定义称谓和至少一个空白姓名后，自动规整按辈分/支系及录入先后生成多排，人员、文字和空白占位均不丢失。
- 规整后小字和保存内容同步；点击撤销后两者恢复原分排。规整后继续编辑、增删或拖动时，“撤销整理”失效，不覆盖新内容。
- 五排夫妻名单在不点击自动规整时，预览仍保持五排；`generateSmall()` 不得自行合并相邻夫妻排。人工拖成同排后，预览才按同排显示。
- 电脑详情页有自动规整和撤销，但 DOM 中没有小字浮窗；原完整碑面预览、复制、导出、拖动和保存正常。
- 订单列表输入错误口令后立即再次出现密码输入框；连续输错可继续重输，取消不报“列表查询失败”，下一次操作还能输入；正确口令后查询成功。
- 保存失败或平台明确超时后表单/草稿保留并可重试；保存期间重复点击不产生第二次写入，普通业务错误不泄露底层错误文本。
- 模板、二维预览、图片导出、3D 入口和三个订单云函数鉴权无回归。

## 监控与止损

观察首个发布窗口内的前端加载错误、静态资源 404、订单查询/保存失败率、重复订单反馈和预览分排反馈。出现以下任一情况立即停止扩量并回滚：

- 新建、详情加载、保存或列表查询回归；
- 错误口令后无法继续输入，或未验证口令被缓存；
- 自动规整丢人、跳过空白姓名、错误配对，或撤销覆盖后续人工编辑；
- 小字预览与当前名单分排/最终保存不一致，尤其是五排被隐式减少；
- 手机固定预览遮住关键名单操作且无法收起，或电脑详情页意外出现浮窗；
- 保存期间产生重复写单。

## 回滚

1. 将静态站点版本指针切回发布前备份的完整 H5 目录，不做文件级混合回退。
2. 清理 CDN/浏览器层对入口 HTML 的缓存，使资源清单与旧版本一致；带哈希的旧静态资源可继续保留。
3. 回查手机三阶段新建、电脑详情、名单预览与订单列表/保存主链恢复；本需求没有数据库或服务端契约变更，无需数据回滚。
4. 保留失败版本的构建哈希、浏览器/设备信息和脱敏日志，仅用于定位；不得记录姓名、日期、名单、音频、识别文本或媒体内容。
